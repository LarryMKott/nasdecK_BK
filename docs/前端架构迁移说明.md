## 二、决策记录（与方案的差异，均为有意为之）

| 决策 | 理由 |
|---|---|
| **不引入 axios，fetch 保留为传输引擎**（方案示例用 axios） | ① fetch 原生 `credentials + cache:'no-store' + AbortController` 超时，XHR 无 cache 语义，飞牛 WebView 旧内核可能缓存轮询响应；② 全部调用点已按 `r.ok/r.json()` 语义验证过网关 404→200 怪癖（2026-09-10 真机铁律）；③ 单文件产物不引入额外运行时。分层目标（统一基址/超时/错误）由 client.ts 完整达成 |
| ~~**路由静态 import，不做 `() => import()` 懒加载**（方案六节）~~ | **已被 2026-09-29 拆包推翻**（见第四节）：产物去 singlefile 改多文件后，懒加载重新有收益，12 个视图已全部改为 `() => import()` |
| **面板私有数据不进 pinia**（方案 3.2 的收敛执行） | 只收真正全局的：主题/侧栏/新鲜度。各页轮询数据留在业务 composable，避免全局 store 膨胀 |
| **v-html 三页顺延下沉** | 见上节；机制保留比强改模板风险低 |

## 四、多文件产物拆包（2026-09-29，去 singlefile）

**动因**：单文件产物随页面增长无限膨胀（拆包前 1.8MB，其中 12 张插画 PNG 的 base64 内联占约 1.4MB）；
弱网/断网下一次下载失败即整包重来，浏览器缓存也完全用不上。

**改动**：
- `vite.config.ts`：去掉 `vite-plugin-singlefile` 与 `inlineDynamicImports`；`manualChunks` 把
  vue/vue-router/pinia 单列 vendor chunk；`base './'` 保留（相对路径经网关与直连两种入口均正确解析）。
- 路由 12 个视图全部改 `() => import()` 懒加载，每页各自成 chunk（3.7–43KB）。
- `assets/icons.ts`：12 张 `ui/images/icon-*.png` 从 `?inline` base64 内联改为常规导入，
  Vite 发成 `assets/icon-*.png` 独立 hash 文件（入口 JS 随即从 1.4MB 降到 15KB）。
- 后端 `staticpages.py` 新增 `/assets/{path}` 与 `/vue/{path}` 两条静态资源路由
  （目录钳制防穿越 + hashed 资源 `immutable` 一年长缓存；入口 `/`、`/vue`、`/vue/` 仍 no-store）。
  **注册顺序约束**：`/vue`、`/vue/` 必须先于 `/vue/{filepath:path}`，否则空 filepath 被 path 通配吃掉、旧入口 404。
- `ui/index.cgi` 零改动：`index.cgi/` 之后的路径原样转发到 Flask 根，
  `./assets/*` 相对解析落点（`/assets/*` 与 `/vue/assets/*`）均被上述两条路由覆盖。

**产物形态**（`templates/vue/`，仍随仓库提交）：入口 HTML 2KB（引用入口 JS 15KB + vendor 99KB + CSS 76KB）
+ 12 个路由 chunk + 12 张插画 PNG，合计约 1.6MB，单文件最大 99KB。首次加载只拉入口三件套（约 200KB）。

**验证**：pytest 132/132、check_layers 0 违规、vitest 46/46、vue-tsc 0 错误；
TestClient 冒烟 11 例全过（/、/vue、/vue/、/vue/index.html、/assets/*、/vue/assets/*、穿越/缺失 404、缓存头正确）。
