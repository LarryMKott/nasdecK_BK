## 一、环境事实与前置决策（阶段 0 勘察实测）

### 1.1 本机（飞牛 NAS，用户 zcode）实测结论

| 事实 | 影响 |
|---|---|
| `/vol1` 为 btrfs + `trimacl` 挂载，所有文件 stat 显示 mode `000` | 权限位不可信；不能依赖 chmod/getfacl 常规语义 |
| 文件**创建 / 读写 / rename / chmod 后再读**全部正常（已实测排除 chmod 理论） | Python 层面拆分脚本可正常工作 |
| `git init` 在 `/vol1` 上失败：`error: opening .git/config: Permission denied`（失败点特定于 git init 的 config 写入序列；/tmp 上完全正常） | git 基线需绕开（见 1.2 决策） |
| 两个 git：`/usr/local/bin/git` 2.43（Synology 包，**缺 remote-https**，勿用）与 `/usr/bin/git` 2.39.5（系统，功能完整） | 一律显式用 `/usr/bin/git` |
| `/tmp` 是 ext4 独立分区（非 tmpfs，断电不丢） | git-dir 放 /tmp 可持久 |
| 系统 python3 可用；pip 需网络（GitHub 此前可达，PyPI 预计无碍） | venv 安装 fastapi/uvicorn/httpx/pytest/pyflakes |

### 1.2 前置决策

1. **git 布局**：work-tree = 本项目目录，git-dir = `/tmp/nasdash.git`（分离布局）：
   `/usr/bin/git --git-dir=/tmp/nasdash.git --work-tree=/vol1/1000/apps/zcode/nasdash ...`
   首选尝试方案 B（/tmp init 后把 `.git` 整体 mv 回项目目录，文件经跨盘 mv 即普通创建，测试 commit/status 可用则转常规布局）；两案都失败再退 `/tmp` git-dir 案。
2. **拆分执行方式**：不做手工逐行切割。写一次性 AST 拆分脚本（按顶层符号 + 前导注释整体搬迁，杜绝切进函数体），配合 pyflakes 未定义名迭代 + 自动符号表补 import。脚本提交到 `scripts/migration/split_app.py` 留档。
3. **切换策略**：旧 app.py 在阶段 6 前保持原样可用（大爆炸 cutover），中途测试始终对旧文件跑、恒绿；阶段 6 一次性切换并跑路由奇偶校验。
4. **状态归属细化**：`state.py` 只收真正跨模块读写的 6 项（`_TEMP_SNAP(+LOCK)`、`_CPU_USAGE_CACHE(+LOCK)`、`FAN_LOCK`、`FAN_TARGETS`）；`_metrics_prev/_cur`、`_db_lock`、`_CPU_POWER_EMA` 等单一功能区内部的状态随归属模块私有化（与重构计划 2.2 节的微调在此备案）。
5. **重赋值型 global 的机械变换**：`global _X` + 赋值 → `import backend.state as _state; _state._X = ...`（模块属性写），逐处 grep `^global` 清单化处理。
