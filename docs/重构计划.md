# nasdash 后端重构计划：FastAPI 迁移 + 模块化拆分

> 状态：**实施中**（按「八、开发计划」分阶段实施，进度见 docs/开发计划.md）
> 范围：仅后端（app.py → backend/ 包）；前端、API 契约、部署方式保持不变
> 基线：app.py 共 11,251 行 / 54 条路由装饰器（58 个 path-method 对）/ 6 条常驻线程，单文件 Flask 应用（v2.3.3）

## 硬性规范（最终标准，2026-09-27 指令）

1. 保持原有 Flask 业务逻辑、接口入参、出参、状态码完全兼容，前端无需修改
2. FastAPI 0.100+、**Pydantic v2**、**SQLAlchemy 2.x**（history.db 数据层用 SQLAlchemy 2.x Core 重写，**表结构与现有 history.db 完全一致**，旧数据无缝续用）
3. 依赖注入替代 Flask 装饰器钩子（`require_admin` 装饰器 → `Depends`；`flask.request/g` → 注入的 `Request`，本项目无 `g` 用法）
4. 全部接口编写 Pydantic 请求/响应模型：请求体经模型校验（宽松配置 extra=allow + 字段可选，**不拒绝历史前端可发送的任何载荷**）；响应模型挂 `response_model` 供 OpenAPI 文档展示，但端点实际返回 `JSONResponse` 透传（FastAPI 对 Response 返回值跳过模型过滤），**保证出参字节级兼容**
5. 统一全局异常处理器（含 403 网关鉴权体、body 解析失败、兜底 500，均返回与现有约定一致的 `{"ok": false, "error": ...}`）
6. 生成 OpenAPI 自动文档（/docs、/openapi.json），保留原 Flask 全部功能
7. 代码带注释；交付 `docs/FastAPI迁移说明.md`（目录结构 + Flask 差异点）
8. 不过度封装，代码可直接运行；配置点显式标注（TRIM_PKGVAR / TRIM_SERVICE_PORT / NAS_DASH_GATEWAY / APP_SOCKET / GATEWAY_PREFIX）
9. 认证决策：维持飞牛网关 Header 身份（X-Trim-*），**不引入 JWT**——网关已完成登录态校验，加 JWT 会破坏网关信任链

## 一、背景与目标

### 1.1 现状

nasdash 后端是 **11,251 行的单文件 Flask 应用**（`app.py`），承担：硬件采集（storcli / smartctl / sensors / mdadm / dmidecode / ethtool / RAPL）、风扇 PWM 控制、SQLite 历史存储、告警与健康报告、50 条 HTTP API。部署形态为飞牛OS FPK 包，经 `ui/index.cgi`（bash+curl）反代到 `127.0.0.1:9800`，或统一网关 Unix Socket 模式。

### 1.2 目标

1. **Flask → FastAPI + uvicorn**：生产级 ASGI 服务器替代 werkzeug 开发服务器
2. **模块化超拆分**：单文件 → `backend/` 分层包（约 35 个模块），依赖单向无环
3. **修正不合理设计**：import 期副作用、循环依赖、悬空引用、跨区 global 直改等（见「六」）

### 1.3 三条铁律

| 铁律 | 含义 |
|---|---|
| **API 契约冻结** | 50 条路由的 path / method / 状态码 / JSON 结构逐条不变，Vue 前端零改动 |
| **采集逻辑原样搬迁** | storcli / SMART / sensors 等解析器逐函数迁移，只改 import，不改逻辑 |
| **同步端点跑线程池** | 现有代码全是阻塞 subprocess 调用，FastAPI `def` 端点自动进 anyio 线程池（等价原 `threaded=True`），**不盲目 async 化**；后台循环保持 threading 线程 |

## 四、FastAPI 迁移要点（契约保持的关键）

| # | 要点 | 说明 |
|---|---|---|
| 1 | 端点全部 `def` 同步函数 | 自动进 anyio 线程池，不阻塞事件循环；仅 `/manual` SSE 与 body 读取依赖用 async |
| 2 | 响应映射 | `jsonify(x), code` → `JSONResponse(content=x, status_code=code)`；**403 鉴权错误体保持 `{"ok":false,"error":...}`**（不用 HTTPException，避免变 `{"detail":...}`） |
| 3 | POST body | 同步端点无法 `await request.json()` → `deps.json_body` 异步依赖预读，解析失败返回 `None`，精确复刻 `get_json(silent=True)`，**避免 FastAPI 默认 422 改变错误契约** |
| 4 | 网关模式 | `NAS_DASH_GATEWAY=1` → uvicorn UDS（bind 后 `chmod 0o777` 保持网关跨用户可访问）+ `127.0.0.1:TRIM_SERVICE_PORT` TCP 侧车（线程内 `uvicorn.Server`、禁信号处理器）；`_PrefixMiddleware` 改写为纯 ASGI 中间件；本地模式 → `uvicorn.run(host, port)` |
| 5 | SSE | `stream_with_context` → `StreamingResponse`（media_type: text/event-stream） |
| 6 | 静态文件 | `send_from_directory` → `FileResponse`；目录基准从 `__file__` 改 `paths.REPO_ROOT` |
| 7 | 路由组织 | 50 条路由按域挂 `APIRouter`（8 组）；同一 path 双方法保持双端点 |
| 8 | 线程模型 | 后台采集/风扇循环保持 threading；uvicorn 不改变线程语义 |

## 五、不合理设计修正清单

1. **import 期副作用显式化**：stderr tee、配置迁移、storcli 探测、`_restore_fan_modes()`（写 sysfs）、6 条线程、`_init_history_db()` 全部收进 `serve.main()` 启动序列：`install_error_ring → migrate → init_history_db → restore_fan_modes → start_background_workers → serve`。对 FPK 部署（`python3 app.py`）时序等价；对测试 import 零副作用
2. **`_StderrTee` 适配 uvicorn 日志格式**：原 werkzeug 访问行正则在 uvicorn 下失效（`/api/errors/*` 路径含 error 字样会被误收入错误圈）→ 正则同时识别 uvicorn 访问行，维持「仅 5xx 入圈」
3. **循环依赖三处解法**：`get_fan_status` 下沉；metrics 主循环上提 daemon（由它调用 collectors/history/schedule，自己不被依赖）；`_SYSTEM_CACHE` 失效用 API
4. **悬空引用修正**：裸名 threading、`_fcs_status_cached._started` 函数属性
5. **`_parse_ver` 双定义保义拆名**（两算法不同，均原样保留）
6. **跨区 global 收编**：`_cc_sched_last_check` 归 schedule 并暴露到期查询
7. **明确保留项**：`_render_report_html`（约 700 行单函数）**原样搬迁不拆**——报告 HTML 输出无测试覆盖，拆它风险大于收益，标记为已知技术债
8. **明确保留项**：运行期惰性线程（FCS 刷新、自检 worker、后台改名）随模块迁移、不改机制

## 七、分阶段开发计划

> 每阶段独立可验证；任一阶段失败 `git checkout` 回基线。旧 app.py 在阶段 6 前保持原样可用（大爆炸式切换，避免中途双绿维护）。

- 写 `scripts/extract_routes.py`：正则静态抽取旧 app.py 全部 50 条路由 (path, methods) → `routes_baseline.json`（**不 import 旧文件**，因其 import 即写风扇 sysfs）
