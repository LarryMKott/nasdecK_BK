## 一、前置决策（方案落地差异，实施前定案）

方案是理想目标架构；与本项目现状对撞后有 8 处需要定案。**以下决策即最终标准**，实施中不得临时变卦：

| # | 议题 | 方案原文 | 本项目决策 | 理由 |
|---|---|---|---|---|
| 1 | import 前缀 | 示例用 `from domain...`（顶层包） | 一律 `backend.domain...` / `backend.application...` 等带 `backend.` 前缀的绝对导入 | 与现有 55 模块、pytest patch 目标（`backend.shell` 等）一致；不加 sys.path hack |
| 2 | 同步/异步 | 示例用例与采集器均 `async def` | **同步优先，不 async 化**：采集器保持阻塞 subprocess，UseCase 为同步方法，FastAPI `def` 端点自动进 anyio 线程池 | 继承 FastAPI 迁移铁律 3；现有 6 条 threading 后台线程机制不改；盲目 async 化 = 全量重写采集层，违背"存量复用"原则 |
| 3 | URL 契约 | `/api/v1` 前缀 + endpoints 按页面拆分 | **路径逐字节不变**（58 对 path-method 冻结），`presentation/api/endpoints/` 直接沿用现有 8 个路由文件，不引入 v1 | 继承 FastAPI 迁移铁律 1；Vue 前端与 index.cgi 反代零改动；版本化留作远期可选项 |
| 4 | DI 容器 | `main.py` 组装 + `Depends()` 直接实例化 UseCase | `main.py` 纯手工构造组装根（**不引 DI 框架**），容器挂 `app.state.container`，`presentation/api/dependencies.py` 提供 `Depends(get_xxx_usecase)` 访问器 | 方案示例的裸 `Depends()` 会在 import 期构造无依赖对象，是错的；同时维持"不过度封装"规范 |
| 5 | 启动入口 | `backend/main.py` 即入口 | FPK 启动链保持 `$PYTHON app.py`（`/app/app.py` 软链自愈依赖此路径）→ `backend.main.run()`；`main.py` 是**组装根**而非 uvicorn 入口 | 打包路径是平台契约；`serve.py` 启动序列（错误圈→配置迁移→历史库→风扇恢复→线程→uvicorn）并入 main.py 生命周期 |
| 6 | 后台任务 | `tasks/` 用 asyncio | `backend/tasks/` 保持 threading 定时循环（6 条线程从 daemon.py 平移），**循环体内改调 UseCase**；不引入 asyncio/Celery/Redis | 方案只要求"复用 UseCase + 不引 Celery"，threading 已稳定运行；asyncio 改造无业务收益 |
| 7 | 生命周期钩子 | `@app.on_event("startup")` | FastAPI **lifespan** 上下文管理器 | `on_event` 自 FastAPI 0.93 起废弃，方案示例代码过时 |
| 8 | 全局缓存/快照 | （未提及） | `state.py` 快照、TTL 缓存、`_FAN_ENUM_CACHE` 等单点状态**平移进 infrastructure 原样保留**，不为 DI 而强行实体化；domain 只收纯规则 | 20+ 项全局状态在 FastAPI 迁移中刚完成单点归属，再实体化是第二场大手术且无测试收益；在「六」记为远期可选项 |

**继承的三条铁律**（FastAPI 迁移已验证，继续有效）：
1. **API 契约冻结**——58 对路由的 path/method/状态码/JSON 结构逐字节不变；
2. **采集逻辑原样搬迁**——解析器逐函数迁移，只改 import 与归属层，不改逻辑；
3. **同步端点跑线程池**——`def` 端点 + threading 后台循环，不盲目 async 化。
